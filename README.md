# BUCAZU — куда переехать с вашим бюджетом

Живой сайт: https://vlad1ewt4.github.io/bukazu-budget/

Сначала человек вводит общие накопления, чистый ежемесячный доход, постоянные обязательства, число людей и срок. Затем сравнивает 9 направлений в 8 странах. Каждая карточка показывает ежемесячные расходы, сумму на старте, разницу между доходом и расходами, остаток в конце срока и недостающую сумму. Накопления не делятся между странами: страны — альтернативные сценарии. Цены, депозит и предоплата сохраняются отдельно для каждого направления в пределах вкладки.

Дизайн использует предоставленное владельцем изображение BUCAZU, графитовый фон, белые блоки и лаймовые акценты. Чужой дизайн-референс не включён в репозиторий.

**Статус первой версии:** расчёты, сравнение, адаптивный интерфейс и загрузка официальных курсов работают. Полной базы актуальных расходов по странам пока нет. Поэтому без заполненных цен направление не получает оценку доступности. Кнопка «Посмотреть пример» включает девять явно вымышленных сценариев; их нельзя использовать как цены городов. Выход из примера восстанавливает предыдущие данные пользователя.

Калькулятор на русском языке: разовые и ежемесячные расходы, общий и личный бюджет, депозит, предоплата, резерв, доход и помесячный денежный план. Работает в браузере без установки библиотек. Личные суммы никуда не отправляются и не сохраняются после закрытия вкладки.

## Что работает сейчас

- Точный расчёт по введённым суммам с арифметикой в целых копейках.
- Валюта каждой строки: RUB, USD, EUR, VND, THB, IDR, MYR, GEL, AMD, RSD, TRY.
- Автоматическая загрузка курсов Банка России; MYR рассчитывается через официальный USD/MYR Bank Negara Malaysia. Сохраняются даты обоих компонентов.
- Задание фактического курса вручную и наценки конвертации.
- Независимые расходы для выбранных направлений: Дананг, Нячанг, Бангкок, Бали, Куала-Лумпур, Тбилиси, Ереван, Белград, Анталья.
- GitHub Actions обновляет данные дважды в сутки. Это расписание, не гарантия точного времени: GitHub может задерживать запуск; для неактивных публичных репозиториев расписания могут отключаться.
- При ошибке источника предыдущая дата не становится сегодняшней. Курсы старше 7 дней и ориентиры старше 45 дней не используются автоматически.
- Пустые включённые расходы блокируют результат. Неиспользуемую статью нужно явно исключить; нулевая цена вводится как 0.
- Учебный пример с вымышленными суммами явно помечен. Старые цены из гайда не импортированы.

## Что ещё нужно подключить для автоматических цен

Текущая версия не выдаёт вручную введённые или старые цены за живые рыночные данные. Средние цены города требуют действующего источника данных и прав на их отображение.

Подготовлен адаптер Numbeo для аренды квартиры с одной спальней вне центра, домашнего интернета, месячного проездного и мобильного тарифа. Данные запрашиваются для выбранного города без подстановки соседних городов. Отдельно сохраняются месяц цен, дата запроса и число наблюдений. При менее чем трёх наблюдениях значение не предлагается. Сопоставление категорий сделано по справочнику API, а не выдуманным кодам. Подключение не проверено на платном API без ключа.

Владелец должен приобрести/иметь лицензию, разрешающую конкретное отображение данных, в том числе их присутствие в статическом файле и истории GitHub. Если лицензия этого не допускает, понадобится серверный шлюз и другой режим публикации, а не добавление секрета в JavaScript.

После проверки лицензии:

1. GitHub → Settings → Secrets and variables → Actions → добавить секрет `NUMBEO_API_KEY`.
2. Добавить переменную `NUMBEO_DISPLAY_LICENSE_CONFIRMED=true` только при наличии соответствующих прав.
3. Actions → Refresh official data → Run workflow.
4. Проверить реальные ответы, соответствие категорий и показываемые даты. Ключ хранится только в Secrets и используется в заголовке запроса; он не попадает на страницу.

Еда, страховка, визы и документы остаются пользовательскими суммами: для них нельзя надёжно заменить личную корзину или нужный полис одной средней ценой. Билеты и конкретное жильё под даты также требуют отдельного поставщика предложений и перепроверки итоговой стоимости перед покупкой. Эта версия ничего не бронирует и не обещает будущую цену.

## Как устроен расчёт

1. Каждая сумма переводится в рубли отдельно. Цена «на человека» умножается на число путешественников, «на всех» — один раз. Аренда фиксированно относится ко всему жилью.
2. Наценка обмена повышает рублёвую оценку иностранных расходов и уменьшает рублёвую оценку иностранных доходов/накоплений. Для рублёвых строк она не применяется. Это упрощение для планирования, не курс конкретного банка. При ручном курсе, уже включающем комиссию, установите наценку 0, чтобы не учитывать её повторно.
3. Процент запаса увеличивает разовые и месячные расходы на переезд и жизнь. Депозит и фиксированные личные обязательства не увеличиваются. Резерв считается по полным месячным расходам с запасом и обязательствами плюс отдельная сумма на выезд.
4. В момент старта оплачиваются разовые затраты, депозит и выбранное число месяцев аренды вперёд. Предоплата ограничена горизонтом расчёта и не дублируется в следующих месяцах.
5. Каждый месяц остальные расходы списываются до дохода; доход приходит в конце месяца начиная с указанного месяца. Нужные деньги на старте — максимальная накопленная потребность в средствах до очередного дохода плюс резерв.
6. Возврат депозита заранее не учитывается. Общая стоимость периода показывается без возвратного депозита и неиспользованного резерва; эти суммы представлены отдельно.

Расчёт относится к целым месяцам после заселения. Для временного жилья до этого периода есть разовая строка. Продления виз, школа, дополнительные поездки и другие личные затраты вводятся отдельно в соответствующие статьи. Не включайте одну и ту же оплату одновременно в разовую и месячную строку.

## Запуск и проверка

Требуется Node.js 22 или новее. Установка пакетов не нужна.

```sh
npm test
npm run update-data
npm start
```

Открыть http://127.0.0.1:4173. Для ручного расчёта достаточно RUB; остальные валюты используют загруженный снимок или явно введённый курс.

## Размещение на GitHub

Сайт опубликован через GitHub Pages из открытого репозитория с разрешения владельца. После изменений в main и обновления данных сайт публикуется автоматически. Мобильная версия включает нижнюю навигацию, раскрытие полного списка направлений, крупные поля сумм и помесячный план в карточках. Личные суммы не сохраняются в репозитории.

Исходный код и обновляемые данные могут храниться в закрытом репозитории. GitHub Pages — отдельное действие: закрытый репозиторий сам по себе не означает закрытый доступ к сайту. Доступность Pages для закрытого репозитория зависит от плана GitHub.

Когда публикация разрешена, включите Pages → Source: GitHub Actions, установите переменную `ENABLE_GITHUB_PAGES=true` и запустите Publish calculator to GitHub Pages. Workflow публикует только интерфейс, расчёт и предназначенные для него данные. Он не публикует скрипты, тесты или секреты.

Для API-квот и безопасности не запускайте платные обновления из браузера каждого посетителя. Запрашивайте данные по расписанию; ручная кнопка на странице перечитывает последний опубликованный снимок, а не обходит API-лимиты.
